# Booking Register — notes for Claude Code

Installable web app (PWA) for a 6-apartment homestay's booking register. Plain HTML/CSS/ES modules, **no build step**, hosted on GitHub Pages; data in Supabase.

## Structure
- `js/calc.js` — pure calculation functions. **Single source of truth for the form preview**; must stay in step with the generated columns in `supabase/schema.sql`.
- `js/app.js` — UI, Supabase queries, realtime. Loads `@supabase/supabase-js` pinned from jsDelivr (`+esm`).
- `js/config.js` — Supabase URL/anon key, business name, booking types.
- `supabase/schema.sql` — idempotent schema: `profiles` (owner/staff), `houses`, `bookings` with generated money columns, RLS, serial/audit triggers.
- `sw.js` — app-shell cache. Bump `VERSION` on every change to app files.

## Rules
- Money columns: input columns are `tariff, gst_pct, food_bill, extra_bed, firewood, gas, advance_ota, paid_cash, cash_received, tips, paid_upi` (plus `extra_bed_days, firewood_days, gas_days`). Calculated (never written by the app): `nights, gst_amount, total_tariff, gross_total, total_balance, total_balanced`.
- If you change a formula, change it in **both** `js/calc.js` and `supabase/schema.sql` (provide an `ALTER TABLE` migration in `supabase/migrations/`), and update `tests/calc.test.mjs`.
- Tariff = whole-stay room charge before GST. Tips are excluded from the balance check.
- Extra Bed, Firewood and Gas are charged **per day** (`EXTRAS` in app.js): Yes/No + Days on the form. Yes locks in the current rate per day from the `settings` table (`<name>_rate` keys) and fills Days with the nights (follows date changes until staff type a number). Saved as `<name>` = rate × days (`extraAmount` in calc.js) plus `<name>_days`; the rate is recovered as amount ÷ days (`extraRate`), so a later rate change never alters past bookings. Amount above 0 shows as Yes; old rows with amount but 0 days count as 1 day. Bill shows "N days × ₹rate".
- Guest bill: `js/bill.js` builds it from the **saved** booking (Print bill asks to save unsaved edits first). Business details come from the single-row `business_profile` table (owner edits in Settings). `assign_bill_no(uuid)` RPC fills an empty `bill_no` with `<prefix>/<FY>/<0001>`, FY by check-out date; a manually typed bill no. is kept. The signature is a PNG data URL in `business_profile.signature` (never commit it: the repo is public); Settings crops it and removes the paper background on upload. Only `#billView` prints (`@media print` in app.css).
- Navigation is a fixed bottom tab bar (`.bottomnav`): Summary (default) · Register · + New booking (`#newBtn`, opens the form sheet, no section change) · Availability (`tab-houses`) · Performance (`tab-perf`). Settings is the gear `#settingsBtn` in the top bar (owner only). Switch sections with `showTab(name)`. Keep fixed elements (toast etc.) above `--nav-h`.
- Summary tab = Today cards (`renderToday`: occupied tonight, arriving, leaving, from `state.upcoming`, which includes today's check-outs) + the Totals table.
- Totals table (Summary tab): Today / month so far / financial year so far (from 1 Apr) / year to date (**calendar year: 1 Jan to today**) / **Upcoming** (check-ins from tomorrow, `UPCOMING_END`). Every period except Upcoming ends **today**, so future bookings count only under Upcoming. By **check-in date**, all apartments (`reportPeriods`, `periodTotals`, `periodsSpan` in calc.js; `loadTotals` fetches from the earliest period start to the latest end). On phones (<600px) one column shows at a time via the `#totalsSeg` switcher.
- Availability grid (`renderCalendar`): apartments across, days of `state.calMonth` down; built by `availabilityGrid`/`occupancy` in calc.js (a stay occupies check-in up to, not including, check-out; 2+ stays on a night = double booked, striped). Colours: `houses.color` key (migration 006; owner picks in Settings), styled by `.c-<colour>` tokens (light + dark) in app.css; `houseColour()` falls back to the apartment name, then the id. Free cell → `openSheet(null, {house_id, check_in, check_out})`. Must fit **all apartments across with no sideways scroll** on phones: under 760px the grid uses short labels (`.ls`: first word of apartment and guest name via `shortName()`, booking type hidden), slimmer rows and narrow date/free columns; full labels are `.lf`. Don't reuse the class `today` on table rows (`.today` is the Summary section, a flex box); the row class is `is-today`.
- Themes: Light (white + blue `#1f5fd1`) is the default; Dark (black + blue `#5b9bff`) via `<html data-theme="dark">`, toggled by `.theme-toggle` and kept in `localStorage.theme` (an inline script in index.html applies it before first paint). Do **not** use `prefers-color-scheme`: the device setting must not switch the app to dark. Dark overrides go under `:root[data-theme="dark"]`. The guest bill keeps its own fixed light colours.
- Performance tab: `js/perf.js` (pure metrics, tested in `tests/perf.test.mjs`): nights counted **on the night stayed**, room revenue = tariff before GST spread over nights, extras spread too; available = apartments × nights; weekend = Fri+Sat nights; per-stay figures (ALOS, extras, unpaid) use bookings that check in during the period. `perfPeriod()` defines periods and their comparison period. `js/performance.js` holds each metric's copy (what / why / tips per status good·warn·bad·none) and builds cards + detail; `js/charts.js` draws SVG/HTML charts (single accent series with the current month emphasised, target line, data-tip tooltips, a "Show the numbers" table). Chart colours `--s1` blue / `--s2` orange were checked with the dataviz validator in both themes. Targets (`target_occupancy|adr|direct|alos`) and OTA commission (`commission_<slug>`) live in the `settings` table; ADR target 0 = compare with the 12-month average. `loadPerf` fetches ~2 years of bookings plus `monthly_history` (migration 007: house_id, ym, nights_booked, nights_available, room_revenue before GST; the table only. Its figures are loaded from a private file and must **never be committed**). In `computeMetrics`, a month with any history rows is taken wholly from history (missing apartment = not open; nights_available 0 = closed) and bookings in it don't add nights or revenue; part-months are pro-rated. Channel/commission/weekend/ALOS come from bookings for every month (`appSold`, `appOnly` cards get a note); extras/unpaid use non-diary bookings only (`diaryless` cards). Periods never run past today (`perfPeriod`: "so far", compared with the same span of days); the current month in trends is counted to today.
- Expenses tab (`tab-exp`, migration 008): `expense_categories` (name, `monthly`/`daily` flags, sort_order; Other daily-only, Maintenance and Kitchen both), `monthly_expenses` (PK category_id+ym, **owners only** via RLS: salaries are private), `daily_expenses` (members read/insert; creator or owner edits/deletes). `monthSheet()` in `js/expenses-calc.js` (tested) rolls daily entries into their line for the month. Monthly view cards: revenue = rooms + extras before GST from `computeMetrics` (history-aware), profit, cost per night sold. Staff see only the Daily view. Owners also get Profit + Cost per night sold cards on Performance (`profitMetrics`/`monthlyProfitSeries` in perf.js: only months with expense rows count; monthly amounts pro-rated for part-months, daily by date; margin target `target_margin`, default 30). `columns()` in charts.js draws negative values downward in `--bad`.
- Booking diaries (migration 009): stays from the 2023–2026 paper/Excel diaries are `bookings` rows with `from_diary = true` (room revenue before GST only; no GST, extras or payments). The data is loaded by private SQL files sent to the owner, **never committed** (guest names, phones, salaries; the repo is public). Diary rows: count in Summary bookings/nights/gross but not Balance after OTA (`periodTotals` → `diary`, `#totalsNote`); show a "Diary" pill instead of Balanced; skipped by the Balanced filter; left out of extras per stay and unpaid (`appStays` in perf.js). Booking type `Unknown` (`UNKNOWN_TYPE` = no source written) has 0% commission and is left out of direct share (`directShare` is of known-source revenue; `unknownShare` shown). In history months bookings still feed channels, commission, weekend/weekday and ALOS, but not nights/revenue. `monthly_food_income` (ym, amount: diary kitchen income) is added to extras for history months (`opts.foodIncome`). Kitchen expense line is monthly + daily. Register is ordered by check-in (diary serials come after app serials) and its months go back to Jan 2023.
- Closed dates (`closed_dates`, migration 009): house_id null = all apartments; end_date = first open night; `direct_only` = closed to direct bookings only (OTAs still sell). `closureOn`/`closureClash`/`DIRECT_TYPES` in calc.js (tested). Grid: free cells get `.shut` (hatched, not counted free) or `.nodirect` ("OTA only", still free). Saving a booking on them warns like a double booking ("Save anyway"). Owner adds/removes them in Settings (`#closedForm`).
- Bottom-bar labels have `.lbl-long`/`.lbl-short` (≤480px: New, Calendar, Stats).
- Business name is "Two Seas Residence" (`BUSINESS_NAME` in config.js, plus index.html title and manifest).
- Escape all user text with `esc()` before inserting into HTML.
- Keep relative paths (the site is served from `/booking-register/` on GitHub Pages).
